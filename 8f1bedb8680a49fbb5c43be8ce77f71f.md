# ASHA — Frontend-Only Demo: Implementation Plan

Create a demo branch that runs entirely in the browser with no Supabase, FastAPI, or AI credentials. Keep `main` untouched. Put all mock data, simulated API, workflow state, persistence, and reset logic in one file: `apps/web/src/demo/demoMock.ts`. Make minimal edits to existing screens to wire them to it.

## 0. Ground rules

- Branch: `demo/frontend-only` from current `main`.
- One connected journey: buyer → leader → member → checker → approver → buyer delivery.
- All mock logic in `demoMock.ts`; screens import functions, never seed data or business rules.
- Real calculations stay in the mock: allocation totals, costing, payout, progress.
- Simulated: auth, AI plan, proof media, voice, persistence, payments.
- No cross-tab sync; same-tab role switching; localStorage persistence.
- Never claim real auth/RBAC/live sync in the demo UI.

## 3. demoMock.ts — single source of truth

Contents:

- Types: Role, DemoMember, DemoOrder, DemoTask, DemoProgress, DemoProof, DemoQualityReview, DemoCostSheet, DemoPayoutSheet, DemoApproval, DemoDelivery, AuditEvent, DemoState.
- Seed data: 1 SHG, 12 Indian-named members with skills/capacity/availability/quality, 1 buyer, 1 two-product order (100 tote bags + 50 jute pouches), staged plan (cutting, stitching, QC, packing).
- State management: load/save `DemoState` to `localStorage` under key `asha-demo-state-v1`; version field for migrations.
- Mock API functions (see §4).
- Deterministic helpers: allocation scoring, costing, payout.
- Reset: `resetDemo()` restores seed; `jumpToPayoutReview()` fast-forwards to a seeded mid-state.
- Audit helper: append event on every mutation.

## 5. Workflow and state transitions

1. Buyer creates order → `REQUESTED`.
2. Leader opens → `generatePlanDraft` → mock AI draft (template-based) → leader edits/accepts → `confirmPlan` → `PLANNING`.
3. Leader → `proposeAllocation` (deterministic scoring) → optional edit with reason → `confirmAllocation` → tasks created → `IN_PROGRESS`.
4. Member → `acceptTask` → `addProgress` → `addProof` (bundled sample image).
5. Checker → `reviewQuality` → accept part / rework rest → `createRework` if needed.
6. Leader → `calculateCostSheet` (real math) → warnings if price < cost.
7. Leader → `calculatePayout` (accepted × rate) → `submitPayout`.
8. Approver → `approvePayout` → payout `APPROVED`; order stays `READY` until delivery.
9. Leader → `markDelivered` → buyer sees delivery record; order `COMPLETED`.
10. Member sees only own earnings; buyer sees no internal data.

## 6. Implementation phases

### Phase A — Demo foundation (0.5–1 day)
- Create branch, add `demo/` folder, `demoMock.ts` skeleton with types + seed + localStorage + reset + role switch.
- Add `DemoProvider`, `DemoModeBanner`, `demoRouteGuard`.
- Wire App routes to demo provider; bypass Supabase auth in demo mode.
- Verify: build passes with no env; refresh restores; Reset works; role switch changes view.

### Phase B — Buyer + leader order flow (0.5–1 day)
- Wire buyer order form → `createOrder`.
- Wire leader orders list/details → mock state.
- Add mock plan generation + confirmation.
- Add order status timeline.
- Verify: buyer submits → leader sees → plan draft → confirm.

### Phase C — Allocation engine (0.5–1 day)
- Implement scoring (skill 30%, capacity 25%, availability 20%, workload 15%, quality 10%).
- Wire propose/edit/confirm.
- Create tasks on confirm.
- Verify: capacity/availability changes alter proposal; confirm creates tasks.

### Phase D — Member tasks + proof (0.5–1 day)
- Wire My Task, accept/reject, progress, proof (bundled sample), My Earnings.
- Add tap-to-play voice with text fallback.
- Verify: member sees only own data; leader sees progress live (same tab).

### Phase E — Quality + rework (0.5 day)
- Wire review queue, accept/rework/reject.
- Create rework task; rejected work unpaid.
- Verify: accepted work payout-eligible; rework not paid.

### Phase F — Costing + payout (0.5–1 day)
- Wire costing inputs + real calculation + warnings.
- Wire payout calc, submit, approve/reject/request-changes.
- Keep delivery separate from approval.
- Verify: cost/accepted-quantity changes update payout; approval does not complete undelivered order.

### Phase G — Delivery, audit, polish (0.5 day)
- Wire mark-delivered + buyer delivery record.
- Add audit trail view.
- Add `Jump to payout review` checkpoint.
- Hide unfinished links; illustrated empty states.
- Verify full 3-min flow twice.
